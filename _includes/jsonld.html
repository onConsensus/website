{%- comment -%} jsonld.html — Schema.org structured data. Two regimes: 1. On a `post` page (any layout: post): emit an `Article` JSON-LD block, or `NewsArticle` for the dispatches link-blog. This SUPPLEMENTS the `BlogPosting` block jekyll-seo-tag emits — search engines accept multiple JSON-LD blocks per page and our Article block carries fields seo-tag does not (articleSection, license, keywords, dateModified fall-through, the publisher's logo as a typed ImageObject). 2. On every other page: emit an `Organization` block describing the publication, plus a `WebSite` block declaring the search action that maps the masthead's `?q=` form to /search/. Implementation notes: - We're hand-rolling JSON. Optional fields use a `,"key": value` (comma *prefix*) pattern so omitting them never strands a trailing comma. - Strings are passed through `jsonify`, which handles escaping. Dates use `date_to_xmlschema` (RFC 3339). - `absolute_url` resolves against `site.url`. Both jekyll-feed and jekyll-seo-tag rely on the same filter; if `site.url` is mis-set every feed breaks alongside us, so we trust it. {%- endcomment -%} {%- if page.layout == "post" -%} {%- assign author = site.authors | where: "slug", page.author | first -%} {%- assign section = site.data.sections | where: "slug", page.section | first -%} {%- if page.section == "dispatches" -%} {%- assign article_type = "NewsArticle" -%} {%- else -%} {%- assign article_type = "Article" -%} {%- endif -%} {%- assign post_image = page.image | default: page.featured_image -%} {%- assign post_description = page.excerpt | default: page.subtitle | default: site.description -%} {%- else -%} {%- endif -%}
