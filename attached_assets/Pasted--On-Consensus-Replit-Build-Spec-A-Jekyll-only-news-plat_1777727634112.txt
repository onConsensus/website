# On Consensus — Replit Build Spec

A Jekyll-only news platform covering decentralized & distributed technologies: governance, research, development, cryptography, and culture. Hosted on **GitHub Pages** at `onconsensus.com`. No databases, no servers, no JS frameworks — just Jekyll, SCSS, and a sprinkle of vanilla JS.

---

## 0. Context Replit needs to know

- **Repo:** `github.com/onConsensus/website` (already exists, mostly empty scaffold).
- **Existing skeleton:** `_authors/`, `_data/`, `_includes/`, `_layouts/`, `_pages/`, `_posts/`, `_sass/`, `images/`, `js/`, `latest/`, plus `_config.yml`, `index.html`, `404.html`, `feed.xml`, `search.json`, `CNAME`, `Gemfile`.
- **`_config.yml` already defines:** kramdown, `jekyll-paginate`, `jekyll-sitemap`, paginate=12, paginate_path `/feed/page/:num`, post permalinks `/feed/:slug`, collections for `pages` / `posts` / `authors`, compressed SASS.
- **Constraints (hard):**
  - GitHub Pages safe mode — only the [GitHub-Pages-supported plugins](https://pages.github.com/versions/) (jekyll-paginate, jekyll-sitemap, jekyll-feed, jekyll-seo-tag, jekyll-redirect-from, jekyll-remote-theme, jemoji, jekyll-mentions, jekyll-relative-links, jekyll-optional-front-matter). **No custom plugins.**
  - No build step beyond Jekyll. No Node toolchain, no Webpack, no Tailwind CLI. SCSS is compiled by Jekyll itself.
  - All content must be authorable in Markdown front-matter by non-developers via GitHub web editor or [Decap CMS](https://decapcms.org) (formerly Netlify CMS).

## 1. Niche styling direction — "Plaintext Cypherpunk Broadsheet"

Most crypto/web3 publications look like SaaS marketing sites: gradients, glassmorphism, dark navy + neon. Differentiate hard.

**The aesthetic: a 1980s mailing-list digest meets *Le Monde diplomatique* meets a Phrack zine.** Editorial, dense, text-first, slightly austere, with cryptographic motifs used as ornament rather than decoration.

### Visual system

- **Palette (light mode primary, dark mode optional):**
  - Paper: `#F4F1EA` (warm off-white, like newsprint)
  - Ink: `#1A1A1A` (near-black, never pure)
  - Rule: `#1A1A1A` hairlines (1px)
  - Accent — single use: `#B8412E` (oxidized red, used only for category tags, drop caps, and the masthead rule)
  - Muted: `#6B6258` (metadata, captions)
  - Highlight: `#E8DFC9` (block quotes, callouts)
- **Type stack (all open-source, served locally):**
  - Masthead/display: **GT Sectra Free** or **Newsreader** (transitional serif, slightly literary)
  - Body: **Source Serif 4** at 19px / 1.65 line-height for long-reads
  - UI/metadata/captions: **IBM Plex Mono** (caps, letter-spaced, small)
  - Drop caps and section openers: **Cormorant Garamond** italic
- **Layout grid:** 12-column with a fixed 680px reading measure. Asymmetric — articles can pull marginalia (footnotes, glossary terms, related-link cards) into a right gutter on desktop.
- **Ornament motifs:**
  - Hash-prefix section markers: `## sha256(governance)` style headings on category pages
  - Merkle-tree dividers between sections (SVG, hand-drawn feel, not generated)
  - PGP-block-styled author signatures at end of articles (`-----BEGIN ARTICLE SIGNATURE-----` ASCII-art block)
  - Block-height timestamps as a secondary date display next to the publish date (e.g., "Block #847,231 / 02 May 2026")
- **Imagery rules:**
  - Featured images are duotoned to ink + paper (CSS `filter` or pre-baked).
  - No stock photography — diagrams, screenshots of code, scanned ephemera, or commissioned illustrations only.
  - All photos get a 1px ink border and a mono caption.
- **Microcopy voice:** declarative, slightly archaic, never hype-y. "Filed under," "Dispatched from," "On the wire," "Errata."

### Why this works

- Crypto media is over-saturated with Bloomberg-aping dark themes. A typographic broadsheet signals serious editorial intent — closer to *Logic(s)*, *Reboot*, *Increment*, or *Asterisk* than to CoinDesk.
- It's cheap to maintain (system fonts + SCSS only) and ages well.
- It scales: longform essays, link-blog dispatches, code-heavy technical pieces all have a place in the grid.

## 2. Information architecture

```
/                          → Front page (latest + featured + sections)
/feed                      → Paginated firehose of all posts
/feed/page/:num            → Pagination
/feed/:slug                → Individual article
/sections/governance       → Category landing
/sections/research
/sections/development
/sections/cryptography
/sections/culture
/sections/dispatches       → Short-form link-blog
/series/:slug              → Editorial series (e.g., "Notes on Rollup Centralization")
/authors                   → Contributor index
/:author-slug              → Author page (collection permalink)
/about
/ethos                     → Editorial standards
/colophon                  → Typography, build, license credits
/contribute                → Pitch guide for writers
/glossary                  → Hover-definitions across the site source from here
/rss.xml, /feed.xml, /atom.xml
/sitemap.xml
/search                    → Client-side search UI
/404
```

## 3. Replit task list (ordered)

> Replit should treat each numbered group as a single PR. Tasks within a group can be done in one commit.

### Phase 1 — Project bootstrap & local dev

1. Clone `https://github.com/onConsensus/website` into the Replit workspace.
2. Add a `.replit` file configured to run `bundle exec jekyll serve --host 0.0.0.0 --port 4000 --livereload`.
3. Confirm Ruby 3.x is available; if not, install via Replit's Nix config (`replit.nix` with `pkgs.ruby_3_2`, `pkgs.bundler`).
4. Update `Gemfile` to pin `github-pages` gem (latest) instead of bare `jekyll`. Run `bundle install`. Commit `Gemfile.lock`.
5. Add a `README.md` at repo root explaining: local dev, content authoring workflow, deploy (GitHub Pages auto-builds on push to `main`), and theme conventions.
6. Add `.gitignore` for `_site/`, `.jekyll-cache/`, `.sass-cache/`, `.bundle/`, `vendor/`, `.DS_Store`.
7. Verify `CNAME` contains exactly `onconsensus.com` (no protocol, no trailing newline issues).

### Phase 2 — `_config.yml` hardening

8. Set `title: "On Consensus"` and `tagline: "On governance, cryptography, and the architectures of trust."`
9. Set `description` (~155 chars) for SEO, `email`, `author` block, `lang: en`, `timezone: UTC`.
10. Add `url: "https://onconsensus.com"` and leave `baseurl: ""`.
11. Add plugins: `jekyll-feed`, `jekyll-seo-tag`, `jekyll-redirect-from`, `jekyll-sitemap`, `jekyll-paginate` (already present). Confirm all are GitHub-Pages-allowed.
12. Add `social:` block with `mastodon`, `bluesky`, `nostr` (npub), `github`, `farcaster`, `rss`. **Omit X/Twitter** to align with the editorial voice; the audience reads decentralized social.
13. Add a `categories:` data structure listing the five permanent sections plus `dispatches` with descriptions and accent colors (still subordinate to the single accent — only used as 2px underlines under the section name).
14. Add `defaults:` for `series` collection (see Phase 5).
15. Add `exclude:` list: `Gemfile`, `Gemfile.lock`, `README.md`, `node_modules`, `.replit`, `replit.nix`.

### Phase 3 — Design tokens & SCSS architecture

16. In `_sass/`, create the following partials and import them via a single `assets/css/main.scss`:
    - `_tokens.scss` — CSS custom properties for colors, type scale, spacing, measure.
    - `_reset.scss` — modern CSS reset (Andy Bell-style).
    - `_typography.scss` — body, heading, drop-cap, blockquote, code, prose rhythm.
    - `_layout.scss` — grid, container, marginalia gutter.
    - `_masthead.scss` — site header with logo + section nav + date strip.
    - `_article.scss` — long-form article styles, including footnotes, pull quotes, figures, captions.
    - `_card.scss` — index/feed card variants (lead, standard, dispatch).
    - `_pagination.scss`
    - `_author.scss` — bylines, author cards, author archives.
    - `_glossary.scss` — `<dfn>` hover popovers via CSS only.
    - `_code.scss` — Rouge syntax highlighting overrides, monospace blocks with line numbers.
    - `_dark.scss` — `prefers-color-scheme: dark` overrides (keep paper→ink contrast inverted; soften reds).
    - `_print.scss` — clean print styles, hide nav, show URLs after links.
    - `_utilities.scss`
17. Self-host fonts in `/assets/fonts/` (woff2 only). Add `@font-face` declarations in `_typography.scss` with `font-display: swap` and preload links in `<head>`.
18. Implement a fluid type scale using `clamp()` based on a 1.250 (major third) ratio.

### Phase 4 — Layouts & includes

19. Build `_layouts/default.html` with: `<head>` (meta, SEO tag, RSS autodiscovery, preloads), masthead include, main content slot, footer include, optional analytics include (default off).
20. Build `_layouts/page.html`, `_layouts/post.html`, `_layouts/author.html`, `_layouts/section.html` (for category landings), `_layouts/series.html`.
21. Create `_layouts/home.html` for the front page with three regions: **Lead** (one hero piece), **Latest** (10 most recent), **By section** (5 columns showing the latest from each section).
22. `_includes/masthead.html` — wordmark, current ISO date + block-height stub, section nav, search affordance, RSS icon.
23. `_includes/article-card.html` — variants via `{% if include.variant == "lead" %}` etc.
24. `_includes/byline.html` — links author → author page, shows reading time (computed from `content | number_of_words | divided_by: 220`).
25. `_includes/footnotes.html` — render kramdown-style footnotes in the marginalia gutter on desktop, inline on mobile, with `IntersectionObserver` to highlight the active note.
26. `_includes/series-banner.html` — shown atop posts that belong to a series, listing all entries.
27. `_includes/related.html` — naive related-posts via shared tags.
28. `_includes/footer.html` — colophon link, license (CC BY-SA 4.0 by default — confirm with editor), RSS/Atom/JSON Feed links, "Verify build" link to the GitHub commit SHA.

### Phase 5 — Collections & content model

29. Confirm `_authors/` collection with frontmatter schema: `name`, `slug`, `bio`, `avatar`, `pgp_fingerprint`, `links` (mastodon, bluesky, nostr, github, website), `joined_date`.
30. Add a `series` collection in `_config.yml` with `output: true`, `permalink: /series/:name`. Each series doc has `title`, `description`, `cover`, `editor`, `status` (open/closed).
31. Standardize post frontmatter:
    ```yaml
    title:
    subtitle:
    author: # slug from _authors
    date:
    section: # one of governance|research|development|cryptography|culture|dispatches
    series: # optional, slug
    tags: []
    excerpt:
    featured_image:
    featured_caption:
    reading_time_override: # optional integer minutes
    canonical_url: # if cross-posted
    license: CC-BY-SA-4.0
    pgp_signed: false # if true, render signature block
    ```
32. Add 6 seed posts (one per section + one dispatch) in `_posts/` so layouts can be tested with real content.
33. Add 3 seed authors in `_authors/`.
34. Add 1 seed series in `_series/` referencing 2 of the seed posts.

### Phase 6 — Front page, sections, and feeds

35. Implement `index.html` using `home` layout. Lead piece is whichever post has `featured: true`; fallback to most recent.
36. For each of the 6 sections, create `_pages/sections/<section>.html` with `layout: section` and front-matter `section: <name>`. The layout filters `site.posts` by `post.section == page.section` and paginates.
37. Build `/feed/index.html` (paginated firehose) using `paginate` from `_config.yml`.
38. Build author archive at `_layouts/author.html` listing all posts where `post.author == page.slug`.
39. Build series archive at `_layouts/series.html` listing posts in publication order with intro from the series document.
40. Generate `feed.xml` (RSS 2.0 via `jekyll-feed`), and add a hand-rolled `atom.xml` and `feed.json` (JSON Feed 1.1) for completeness — both as plain Jekyll templates, no plugin required.
41. Per-section RSS feeds at `/sections/<section>/feed.xml` using a Liquid loop.

### Phase 7 — Search

42. Generate `search.json` as a Jekyll template that emits an array of `{title, url, section, author, date, excerpt, tags}` for every post.
43. Build `/search/index.html` with a vanilla JS client (no framework) that fetches `search.json` once, indexes it with [Lunr.js](https://lunrjs.com) loaded from a self-hosted copy in `/js/vendor/`, and renders results live as the user types.
44. Add a small search affordance in the masthead — a `/` keyboard shortcut focuses the search input on `/search`, and submitting the masthead search redirects there with `?q=...`.

### Phase 8 — Reading experience polish

45. Drop caps on first paragraph of every article (Cormorant italic, 4 lines, accent color). CSS only.
46. Pull quotes as `<aside class="pullquote">` rendered into the marginalia gutter on desktop.
47. Footnotes (kramdown's `[^1]`) styled into the gutter on desktop, collapsed accordion on mobile.
48. `<dfn>` glossary terms: data file at `_data/glossary.yml` with term → definition pairs. A small Liquid include scans rendered HTML at build for known terms? — **simpler approach:** authors wrap terms manually in `<dfn data-term="merkle-tree">…</dfn>`, and a tiny JS file looks up the definition from a `<script type="application/json" id="glossary">` block injected into the footer.
49. Reading progress bar at top of post layout (CSS-only with `scroll-timeline` where supported, JS fallback).
50. "Estimated reading time" + "Word count" + "Block height at publish" in article header.
51. Optional **PGP signature block** at end of post if `pgp_signed: true` — render an ASCII-art block with the signature pulled from a sibling file `_posts/<slug>.sig`.

### Phase 9 — Accessibility, performance, SEO

52. All images get explicit `width`/`height` and `loading="lazy"` (except hero).
53. Skip-to-content link, focus-visible styles, `prefers-reduced-motion` honored.
54. Color contrast verified at WCAG AA for all text, AAA for body copy.
55. Semantic HTML — `<article>`, `<header>`, `<nav>`, `<aside>`, `<time datetime="…">`.
56. `<head>` includes JSON-LD `Article` and `NewsArticle` schema for posts, `Organization` for the site.
57. Open Graph + Twitter Card meta via `jekyll-seo-tag`. Override card image per post via `image:` frontmatter.
58. Generate `robots.txt` with sitemap reference.
59. Lighthouse target: 100/100/100/100. No third-party JS by default.

### Phase 10 — CMS for non-technical contributors

60. Add a `/admin/` directory with [Decap CMS](https://decapcms.org) (`index.html` + `config.yml`) configured for:
    - GitHub OAuth via Decap's hosted OAuth (or Cloudflare Worker proxy — document both options).
    - Collections: posts, authors, series, pages.
    - Editorial workflow enabled (drafts → in review → ready) using GitHub PRs.
    - Preview pane styled to match production typography.
61. Document the flow in `README.md`: a contributor logs in at `onconsensus.com/admin/`, drafts a post, submits for review, an editor merges the PR, GitHub Pages rebuilds.

### Phase 11 — Editorial scaffolding

62. Write `/about/index.md`, `/ethos/index.md`, `/colophon/index.md`, `/contribute/index.md` as real, voiced copy (placeholder is fine but mark `TODO` clearly).
63. Add a `_data/sections.yml` with each section's name, slug, blurb, editor, accent treatment.
64. Add a `_data/principles.yml` listing editorial standards (sourcing, conflict-of-interest disclosure, AI-content policy, corrections policy) — surfaced on `/ethos`.
65. Add a `corrections.md` page that lists any post with a `corrections:` array in its frontmatter.

### Phase 12 — GitHub workflow

66. Add `.github/workflows/build-check.yml` — on every PR, `bundle exec jekyll build` with `JEKYLL_ENV=production` and run `htmlproofer` on `_site/` to catch broken links and missing alt text.
67. Add `.github/PULL_REQUEST_TEMPLATE.md` with a checklist for new posts (frontmatter complete, images optimized, reading time set, license confirmed).
68. Add `.github/ISSUE_TEMPLATE/` with `pitch.md` and `correction.md`.
69. Add a `CODE_OF_CONDUCT.md` and `LICENSE` (content under CC BY-SA 4.0, code under MIT — two-license repo, document clearly).

### Phase 13 — Pre-launch QA

70. Run `htmlproofer` locally: no broken links, no missing alts.
71. Validate RSS/Atom/JSON feeds against their respective validators.
72. Test on iOS Safari, Android Chrome, desktop Safari/Firefox/Chrome at 320/768/1024/1440/1920.
73. Verify Decap CMS auth end-to-end with a non-developer test account.
74. Verify the GitHub Pages deploy: push to `main`, confirm `onconsensus.com` serves over HTTPS with the custom-domain certificate.
75. Submit `sitemap.xml` to Google Search Console and Bing Webmaster Tools. Note: search submission is optional for a privacy-respecting publication — discuss with editor.

### Phase 14 — Stretch goals (post-launch, still no plugins)

76. **Webmentions** via [webmention.io](https://webmention.io) — receive-only, surfaced under each post as "Mentions on the open web."
77. **ActivityPub** via a static-friendly bridge like [Bridgy Fed](https://fed.brid.gy) — every post becomes a Mastodon-followable account.
78. **Print-on-demand quarterly** — a build script that compiles a season's posts into a Pandoc → LaTeX → PDF zine, linked from `/print`.
79. **Onion mirror** — host a Tor hidden service mirror, link in colophon.
80. **IPFS pinning** — every release tagged in git also pinned to IPFS via GitHub Action; show the CID in the footer.

## 4. Out-of-scope (for now)

- Comments. Use webmentions or a "Reply via email" mailto link.
- Newsletter. If/when added, use [Buttondown](https://buttondown.com) with a static signup form posting to its API; do not introduce any backend.
- Paywall / membership. The publication is open by design.

---

## 5. Acceptance criteria

The build is "done" when:

- A non-developer can publish a fully-formatted post via `/admin/` in under 10 minutes.
- The home page, a section page, an article, an author page, and a series page all render correctly with seed content.
- Lighthouse scores ≥ 95 across the board on a cold cache.
- `bundle exec jekyll build` produces zero warnings.
- `htmlproofer _site/` passes clean.
- The site is served at `https://onconsensus.com` from GitHub Pages with HTTPS active.
